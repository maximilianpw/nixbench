## Dependency notes

- **001 precedes evaluator changes** because any evaluator repair changes the
  benchmark boundary. New and old runs must become mechanically impossible to
  pool before those changes land.
- **002 precedes 003** because independently authored passing fixtures must
  reproduce the false negatives before evaluator code is relaxed.
- **003 precedes 004** so partial-credit rubrics are written against corrected
  semantic contracts instead of preserving known evaluator defects.
- **004 precedes 005** because statistical reports need validated criterion
  outcomes, failure classes, and measurement-validity states.
- **006 depends on the earlier plans** because a held-out corpus needs the same
  identity, scoring, contract-test, and reporting machinery as the public
  development corpus.
- **007 and 008 should land first** because they close corpus-content and
  isolation-identity leaks without depending on later reporting work.
- **009 depends on 008** so the canonical publication identity includes the
  complete trusted adapter bundle rather than the current launcher-only hash.
- **010 depends on 009** because site export must consume the strict shared
  validator instead of creating a third validation implementation.
- **011 is independent of reporting work but changes corpus contracts**; finish
  it before collecting calibration evidence.
- **012 depends on 009 and 011** because calibration must consume strictly
  validated studies against the final evaluator and contract boundary.

## Intended releases

Treat these as benchmark releases rather than ordinary harness-only changes:

1. Plan 001 reserves `2.0.0-dev`; Plans 002–003 keep that prerelease version
   while prompts/evaluators and accepted solution sets change.
2. Plan 004 completes rubric migration and then finalizes **2.0.0**. No public
   2.0.0 trials may be recorded before Plan 004. If that invariant is already
   broken, Plan 004 must use **3.0.0** instead.
3. Plan 005 is schema/reporting work and may be minor if compatibility fields
   remain unchanged.
4. Plan 006 establishes the next public/private corpus generation and release
   policy.
5. Plans 007–010 are harness/security changes. Schema or identity-field changes
   require the compatibility class dictated by governance; do not silently
   reinterpret an already published manifest.
6. Plan 011 changes evaluator and contract boundaries and therefore requires a
   major corpus release unless 2.0.0 is still an unpublished worktree release.
7. Plan 012 must calibrate the final post-011 corpus digest. Calibration evidence
   from an earlier digest cannot activate the changed corpus.

Do not retroactively rescore historical trials. Preserve their original
artifacts and identify them by their original corpus/configuration metadata.

## Findings considered and rejected

- **Replace objective evaluators with LLM judges**: rejected. It would trade
  known deterministic contract problems for less auditable subjective grading.
- **Remove fake builders entirely**: rejected. They are valuable for fast,
  deterministic structure tests; the fix is to make their interfaces match the
  public contract and accept common equivalent representations.
- **Weight categories to force a balanced headline number**: rejected. Report
  transparent task-, category-, and difficulty-level results instead of hiding
  corpus composition behind editorial weights.
- **Use interval overlap as a model-comparison test**: rejected. Preserve raw
  trials and report clearly scoped uncertainty; do not imply significance from
  overlapping or non-overlapping confidence intervals.
- **Publish private evaluator sources for transparency**: rejected while tasks
  are active. Publish manifests, methods, aggregate results, and retired tasks;
  keep active held-out prompts, starters, references, and checks private.
- **Hide corpus imbalance with category weights**: rejected. Preserve transparent
  task/category reporting and add independent underrepresented tasks after
  calibration.
- **Treat public-corpus publication as uncontaminated evidence**: rejected. The
  public corpus remains inspectable development evidence; stronger claims need
  held-out isolation and rotation.
